# CVaR PSHA Bandit

**Goal, in plain terms:** earthquake engineers need to know how likely severe ground shaking is at a given site — this is called **Probabilistic Seismic Hazard Analysis (PSHA)**. Estimating the *rare, severe* end of that shaking accurately (not just the average case) is expensive with brute-force simulation, because you'd need huge numbers of simulated earthquakes before enough severe ones show up by chance. This project asks: can an AI agent, given nothing but a single numeric reward signal after each attempt (a **scalar reward** — one plain number, no extra hints about the underlying physics), *learn on its own* the mathematically optimal way to focus its simulation effort on the scenarios that matter most for the tail of the risk distribution? "Theoretically optimal" is judged against exact answers proven in the literature (below), not against intuition.

To make that goal precise, three ideas need defining up front:

- **Importance Sampling (IS).** Suppose you want to estimate a probability or average under some "true"/nominal distribution `p` (e.g., "how bad is shaking, given nature's real odds of each earthquake scenario"), but the event you care about is rare under `p`, so plain random sampling from `p` wastes almost all its draws on uninteresting, non-severe cases. IS instead draws samples from a different, cleverer distribution `q` that deliberately over-samples the interesting (e.g., severe) region, then corrects each sample by an **importance weight** `w(x) = p(x)/q(x)` — a number that down-weights samples that `q` over-favored and up-weights ones it under-favored — so that the reweighted average is still a mathematically unbiased estimate of the true quantity under `p`, but computed from far fewer samples. Choosing a good `q` is the entire game; a bad `q` can make estimates *worse* than plain sampling despite using the same or more compute.
- **Value-at-Risk (VaR) and Conditional Value-at-Risk (CVaR).** For a random outcome `Y` (e.g., ground-shaking intensity, or portfolio loss), and a small probability `α` (e.g., 5%), `VaR_α` is the threshold `v` such that `Y` exceeds `v` with probability exactly `α` — informally, "the bad-but-not-worst-case level." `CVaR_α` goes one step further: it is the *average* value of `Y` in that worst-`α` tail, i.e. `CVaR_α = E[Y | Y > VaR_α]` (read: "the expected value of `Y`, given that `Y` already exceeded the VaR threshold"). CVaR is the harder, more information-rich quantity to estimate well, because by definition it only depends on the rarest, most extreme outcomes — exactly the regime where plain sampling is weakest and IS matters most.
- **Logic tree, and epistemic vs. aleatory uncertainty.** A PSHA "logic tree" is a branching structure of alternative scientific models — e.g., different assumptions about which fault ruptures, what magnitude it produces, and how strongly shaking attenuates with distance — with each branch weighted by how plausible it is. The uncertainty over *which branch/model is correct* is called **epistemic uncertainty** (uncertainty from incomplete scientific knowledge; more data or research could, in principle, shrink it). This is distinct from **aleatory uncertainty** — the genuine, irreducible randomness of the physical process itself (even with a perfect model, the exact shaking from a given earthquake still varies randomly run to run). Both kinds of uncertainty appear throughout this project.

## Theoretical grounding

This project's empirical claims are benchmarked against two proven results from:

- Houng, S. E., & Ceferino, L. (2025). Fast probabilistic seismic hazard analysis through adaptive importance sampling. *Bulletin of the Seismological Society of America*, 115(2), 646–662. https://doi.org/10.1785/0120240153
  **Proven result used here:** the *zero-variance-optimal* IS distribution (the proposal `q` that would drive a Monte Carlo estimator's variance all the way to zero — the theoretical best case) for hazard-curve / exceedance-probability estimation ("what's the chance shaking exceeds level `v`?") equals the classical PSHA **hazard disaggregation** distribution, written `q_disagg(s) ∝ p(s) · P(Y>v | s)`. Read this as: "the ideal sampling weight for scenario `s` is proportional to (∝) how likely `s` is a priori (`p(s)`) times how likely `s` is to produce shaking `Y` above the threshold `v` (`P(Y>v | s)`)" — i.e., focus sampling effort on scenarios that are both plausible *and* dangerous.
- Houng, S. E., Ceferino, L., & Abrahamson, N. (2025). Fast propagation of epistemic uncertainty in seismic hazard via adaptive importance sampling. *Bulletin of the Seismological Society of America*, 116(4), 1709. https://doi.org/10.1785/0120250205
  **Approach mirrored here:** propagating epistemic uncertainty as a *continuous* probability distribution over model parameters, adapted iteratively — called **Gaussian Population Monte Carlo Adaptive Importance Sampling (G-PMC AIS)** — rather than as a small set of discrete logic-tree branches. "Population Monte Carlo" means the sampling distribution `q` is refit in rounds ("generations"): draw a batch of samples, use their importance weights to update `q`'s parameters (e.g., its mean and spread), then repeat with the improved `q`.

Neither paper addresses CVaR (tail-mean) estimation, portfolio risk, or reward-driven agents — that is this project's own extension, kept clearly distinguished from their proven results wherever it's used (see `disaggregation.py`).

**What is and isn't proven:** we do *not* have a theorem showing an optimal policy can represent the disaggregation-optimal IS distribution for an arbitrary logic tree. What's below is empirical: RL/bandit agents, given only a scalar tail-reward, are benchmarked against the papers' **closed-form**/proven-optimal targets and against their own reported accuracy, on environments of increasing structure (a flat GMM node → an explicit 3-node logic tree → a continuous epistemic space). "Closed-form" means the answer is computed by plugging numbers into an explicit algebraic formula and getting the *exact* result directly — as opposed to approximating it by running a simulation or an iterative numerical search, which always carries some sampling noise or approximation error. One of the accuracy yardsticks used throughout is **KS-D**, the **Kolmogorov–Smirnov distance**: the largest gap, at any point, between two cumulative probability curves (one from the method being tested, one from the true/reference distribution); it ranges from 0 (identical distributions) to 1 (completely different), and both benchmark papers report it, so it's directly comparable across methods here.

## How each method is defined, and how its policy is trained

This section is a mechanism-level reference: for every method mentioned below, what its **policy** (its current sampling distribution `q`) is made of, what one **episode** means for it, and exactly how an episode's outcome turns into an update to `q`. Skim it once, then use it to look up any method by name while reading the Experiments results further down.

### Building blocks shared by every method

- **Episode.** One complete draw through the environment, from the first random choice down to a realized outcome — either a shaking intensity `Y` (1-node, continuous) or a portfolio loss `L` (spatial). An episode is the unit of "budget": a stated `budget` of, say, 20,000 means 20,000 such draws are simulated in total (in some methods one at a time, in others in batches, as noted per method below).
- **Policy `q`.** The distribution the method is currently sampling episodes from. All the "training" described below is really just "how `q` changes after each episode or batch of episodes." `q` starts equal to (or close to) the nominal/prior distribution `p` and is pushed, gradually, toward regions that produce large importance-weighted tail contributions.
- **The scalar reward every learning method actually sees:** `tail_reward(y, w, v95) = w·y` if `y > v95`, else `0`, where `w` is that episode's importance weight `p(x)/q(x)`. In words: zero reward for any episode that isn't already in the severe tail, and — for episodes that are — a reward equal to the outcome's severity `y`, corrected by the importance weight `w` so that averaging this reward is still an unbiased estimate of the CVaR numerator. **This is the only feedback any of the learning agents receive** — never the closed-form hazard formula `P(Y>v|·)` itself.
- **The running CVaR estimate every method is scored on** (`OnlineCVaRTracker`, defined in the Metrics section below): after each episode, `CVaR_hat = (Σ over tail episodes of w·y) / (Σ over tail episodes of w)` — a running, self-normalized importance-sampling average of `y` restricted to the tail. This is *not* the per-episode reward; it's a slowly-converging population statistic computed by pooling every episode seen so far. A handful of methods (v1, CVaR-CPO, Spatial CVaR-CPO) additionally read this running estimate back out and use it to *shape* the reward, described next.
- **Advantage and baseline.** Most methods below are trained by REINFORCE-style policy gradient: nudge `q`'s parameters in the direction of `∇ log q(sampled outcome) × advantage`, where `advantage = reward − baseline`, and `baseline` is an exponential moving average (EMA) of past rewards (`baseline ← (1−α)·baseline + α·reward`, a slow running mean). Subtracting a baseline that doesn't depend on the current episode's action doesn't bias the update (its own gradient contribution averages to zero), but it does cancel out a lot of episode-to-episode noise, which is what makes these gradient estimates usable at all on a reward this heavy-tailed.
- **"CVaR-optimal policy," precisely.** No method here computes CVaR and then differentiates through it directly. Two proxies are used instead, and worth telling apart because different methods use different ones:
  1. **Reward-shaping toward a CVaR *target*** (v1, CVaR-CPO, Spatial CVaR-CPO): a **dual variable** `λ` (a Lagrange multiplier — a running penalty weight from constrained optimization, not part of `q` itself) tracks how far the running `CVaR_hat` has drifted from a target value, and grows whenever the drift exceeds a tolerance: `violation = |CVaR_hat − target| − cvar_tol·|target|`, then `λ ← max(0, λ + dual_lr·violation)`. The advantage used for the policy update becomes `reward − λ·|CVaR_hat − target|/|target|` instead of plain `reward` — i.e., `λ` grows to discourage the policy from drifting the CVaR estimate too far from where it's supposed to sit, a soft constraint, not the training objective itself.
  2. **Refitting `q` directly toward the closed-form (or empirical) CVaR-optimal target distribution** `q_star(s) ∝ p(s)·E[Y·1{Y>v}|s]` (G-PMC AIS with `target="cvar"`, and JEPA-CVaR v2): here there's no reward-shaping at all — `q` is periodically *re-estimated from scratch* as a weighted average over recently drawn samples, weighted by exactly the `tail_reward` quantity above, which is a Monte Carlo estimate of `q_star`'s defining formula. This is closed-form curve-fitting (moment-matching, defined below), not gradient descent.

### 1-node bandit methods (`Naive MC`, `CEM-IS`, `Exp3`, `REINFORCE`, `q* oracle`, `Disagg-IS oracle`, `CO-STC`)

Policy `q` here is a plain probability vector over the `K` discrete GMM arms (Ground Motion Model branches, each a fixed lognormal `ln Y ~ N(μ,σ)`). One episode = pick one arm from `q`, draw one `Y` from that arm.

- **Naive MC**: `q` is fixed to the nominal prior `p` for the whole run — no learning at all; the "do nothing" baseline.
- **`q* oracle` / `Disagg-IS oracle`**: `q` is fixed for the whole run to the exact, precomputed closed-form `q_star` or `q_disagg` (from `disaggregation.py`) — also no learning; these exist to show the best a *static*, perfectly-informed policy could do, as an upper-bound reference for the learning methods.
- **CEM-IS** (Cross-Entropy Method): runs in batches of `batch_size=500` episodes. After each batch, it looks at the top `elite_frac=5%` of episodes *by raw `Y` value* (the "elites" — not filtered by exceedance, just the highest-`Y` fifth of the batch), counts which arm produced each elite episode, and refits `q` as an exponentially-smoothed blend of "how often each arm appeared among the elites" and the previous `q`: `q ← smoothing·(elite counts, normalized) + (1−smoothing)·q_prev`, with `smoothing=0.7`. No gradients — this is a repeated "keep what worked, refit toward it" update.
- **Exp3**: a per-episode multiplicative-weights update. Each arm has a running `weight`; `q = (1−γ)·(weights/Σweights) + γ/K` (the `γ/K` floor guarantees every arm keeps getting sampled sometimes, so its weight can always be corrected — this is called *forced exploration*). After the episode, only the sampled arm's weight is updated, by an *unbiased* per-arm reward estimate `reward/q[arm]` (dividing by the arm's own sampling probability, so an arm that was rarely tried but got a big reward is credited proportionally, not punished for its rarity) fed through `weight[arm] *= exp(γ·estimate/K)` — weights grow exponentially for arms that keep paying off.
- **REINFORCE**: `q = softmax(logits)`, one free real-valued `logit` per arm. After each episode, the standard categorical policy-gradient update is applied: `logits += learning_rate · advantage · (𝟙[sampled arm] − q)`, where `𝟙[sampled arm]` is a vector that is 1 at the sampled arm and 0 elsewhere — this expression is exactly `∇_logits log q(sampled arm)`, the "score function," so the update is gradient *ascent* on expected reward.
- **CO-STC** (`methods/sto_assign.py`): an adaptation of Pavirani, Claessens, Pinson & Develder (2026), *Control-Oriented Scenario Tree Construction through Reinforcement Learning* (https://arxiv.org/abs/2608.09335). That paper is discrete/combinatorial by design: it fixes a tree topology and *assigns* a fan of sampled scenarios onto the leaves with a set-encoder policy trained by PPO, using the downstream risk-averse control profit rather than a Wasserstein distance to the forecast. Here the topology *is* the K GMM arms. Each batch draws a fan of 128 episodes (atypical `μ` first, groups of 8), assigns them onto the arms, and the leaf masses `q_hat[ℓ] ∝ Σ_{assigned to ℓ} (p/q)·y·1{y>v}` become the IS proposal — paper Eq. 5 with a CVaR tail kernel, skipped when a fan has fewer than 3 exceedances so a lucky body-arm hit cannot lock `q`. Assignment is initialized at ~99% identity (categorical CE) and residual-trained by PPO with an asymmetric critic that sees realized `Y` only at train time. A DeepSets MLP (numpy; not their multi-head attention) stands in for the set encoder. **Never given `P(Y>v|arm)`.** There is no inner battery LP.

### 3-node tree methods (`Hierarchical`, and flat-path baselines `Naive MC`/`CEM-IS`/`Exp3`/`REINFORCE`/`CVaR-CPO`/`CO-STC`)

Here one episode is a full walk down the tree — Source branch, then Magnitude branch, then GMM branch, in sequence — with `Y` drawn only at the very end (a **delayed reward**: every intermediate step gets reward 0, and the tail reward is computed only once, from the leaf). The episode's overall importance weight is the *product*, across the three sequential choices, of that step's `(prior probability chosen)/(policy probability actually used)` ratio.

Two different ways of representing `q` over this tree are compared:

- **Flat** methods (the tree versions of `Naive MC`, `CEM-IS`, `Exp3`, `REINFORCE`, `CVaR-CPO`, and `CO-STC`) collapse the whole tree into one categorical distribution over all `n_paths` complete paths (2 Source branches × 2 Magnitude branches × 3 GMM branches = 12 paths here), and sample a full path in one draw — mechanically identical to the 1-node methods above, just with "arm" replaced by "full path index."  **`CVaR-CPO`** additionally layers on the dual-variable CVaR-drift penalty described above, *and* a crude **trust-region** damping step after each gradient update: the freshly updated `q_new` is pulled back part-way toward the pre-update `q_old`, `q_damped = (1−kl_coef)·q_new + kl_coef·q_old` — limiting how far any single update can move the policy, which is the "lightweight discrete CPO" (Constrained Policy Optimization) referred to by its name; it is explicitly *not* a rigorous CVaR policy-gradient method, just this heuristic damped-dual-ascent scheme. **`CO-STC`** is the same Pavirani et al. (2026) assignment agent as in the 1-node case, with the 12 complete paths as the fixed leaf set.
- **Hierarchical** instead keeps one *small* softmax sub-policy per tree node *and per history so far* (e.g., a separate 2-way choice for Magnitude given "Source=softer" versus given "Source=harder") — the "hierarchical" decomposition is this factoring of one big 12-way choice into three small chained choices, each conditioned on what was chosen earlier. Every episode's leaf reward (shaped by the same advantage-minus-baseline mechanism as REINFORCE above) is applied identically to *every* node visited on that episode's path — i.e., the single scalar credit for a good or bad outcome flows back to all three decisions that led to it, each nudged by its own score function `(𝟙[action] − q_node)`.

### Continuous-epistemic methods (`Naive MC`, `Disagg-IS oracle`, `G-PMC AIS`, `Hierarchical JEPA-CVaR` v1 and v2, `CVaR-BF AIS`, `QR-SRM AIS`)

Here the epistemic uncertainty is two continuous numbers `θ = (θ_μ, θ_σ)` (median-GMPE offset and aleatory-sigma scaling) rather than discrete branches, so `q` is a 2-D Gaussian (mean + covariance) rather than a probability table. One episode = draw one `θ` from `q`, then draw one `Y` conditioned on that `θ` from the *true, un-importance-sampled* aleatory law (only the epistemic draw is importance-sampled; the physical shaking-given-scenario randomness is always sampled honestly, matching how hazard disaggregation is defined).

- **G-PMC AIS** (given the closed-form hazard `P(Y>v|θ)`, or `E[Y·1{Y>v}|θ]` for the CVaR-target variant): runs in batches of `batch_size=300` `θ`-draws. Each batch mixes draws from the current adaptive proposal and a small fixed fraction (`defensive_eps=10%`) drawn straight from the prior — the **defensive mixture** mentioned earlier, which bounds how extreme any single importance weight can get. For every drawn `θ`, it computes the exact closed-form relevance `H(θ)` and an unnormalized weight `p(θ)·H(θ)/q_mix(θ)`; then it refits the proposal's mean and covariance by **weighted moment-matching** — literally the ordinary formulas for a weighted mean and weighted covariance, `mean = Σ(w_i·θ_i)/Σw_i` and similarly for covariance, using those weights — inflates the fitted covariance slightly (`×1.15`, so the proposal doesn't overconfidently collapse) and mixes the new fit into the running proposal with an EMA (`smoothing=0.5`). No gradients anywhere: each batch is a closed-form curve-refit toward the (given) target density.
- **Hierarchical JEPA-CVaR v1**: one episode at a time, trained by the same REINFORCE + dual-variable-shaped-advantage recipe as tree `CVaR-CPO`, but over a continuous Gaussian mean instead of a discrete table, and split into a **Manager**/**Worker** hierarchy that is the direct answer to "short vs. long time horizon": the *episode* itself is always the same single `θ`+`Y` draw for both — there is no different episode length — but the two components of the mean adapt on genuinely different **timescales**:
  - The **Manager**, `mu_m`, is a slow-moving coarse anchor point in `θ`-space, updated every episode but with a small learning rate (`manager_lr=0.02`) — many episodes' worth of gradient nudges are needed to move it appreciably, so it represents the *long-horizon*, "which broad region of θ-space are we focusing on" decision.
  - The **Worker**, a linear readout `(Ww, bw)` applied to a JEPA-encoded embedding of the Manager's *current* anchor, is updated every episode with a *larger* learning rate (`worker_lr=0.08`) — it reacts quickly to fine-tune the sampling mean within whatever region the Manager currently occupies, the *short-horizon* correction.
  A third, separate long-horizon schedule anneals the sampling spread `std` deterministically from `0.9` down to `0.35` over the *entire* budget (unrelated to the Manager/Worker learning-rate split — this is exploration-to-exploitation annealing, not a learned quantity). The per-episode update itself is the Gaussian score-function gradient `score = (θ − mean)/std²` (i.e. `∇_mean log N(θ; mean, std²)`), applied to `mu_m` and to `(Ww, bw)` with their own learning rates, times a Robbins–Monro-decaying step-size multiplier `1/(1+t/lr_decay_horizon)` — a standard stochastic-approximation trick (the step size shrinks over time) needed here because a *constant*-step-size version of this update was found empirically to reach the right neighborhood and then keep drifting randomly under the reward's heavy-tailed noise, rather than settling down. Separately from any of this, a small self-supervised JEPA network (defined next) is trained online, purely to build the embedding the Worker conditions on — it never receives the reward or the CVaR estimate at all.
  - **What the JEPA is and how it trains**, independent of the policy update above: `LightweightJEPA` is a small hand-written (no autograd) neural network with two linear+tanh **encoders** — a *context* encoder mapping `θ` to an embedding `z_c`, and a *target* encoder mapping a 3-number summary of a realized episode's outcome (`build_target_features`: the scaled reward, `log(1+y)`, and `log(importance weight)`, each squashed through `tanh`) to an embedding `z_t` — plus two linear **predictors** that try to predict one embedding from the other. Each encoder also keeps a slow **EMA copy** of itself (updated as `ema ← τ·ema + (1−τ)·online`, `τ=0.98`), and the predictors are trained to match the *EMA* copy's output rather than the live online output (with gradients blocked from flowing into the EMA copy) — the standard BYOL/I-JEPA anti-collapse trick, which prevents the trivial "map everything to the same constant vector" solution that would otherwise trivially minimize a plain self-prediction loss. An added variance penalty (VICReg-style: penalize any embedding dimension whose spread across the batch falls below a target) reinforces this. Trained every `jepa_train_every=16` episodes on a small buffer of recent `(θ, outcome-features)` pairs, using hand-derived gradients (the network is simple enough — linear layers and `tanh` only — that backpropagation can be written out in closed form rather than needing an autograd library).
- **CVaR-BF AIS** (`methods/cvar_bf.py`): an adaptation of Wang, Kim, Hoxha, Fainekos & Panagou (2026), *Reinforcement Learning for Risk Adaptation via Differentiable CVaR Barrier Functions* (https://arxiv.org/abs/2605.21257) — a robotics paper, not a PSHA paper; what transfers is the *architecture*, not the crowd-navigation QP. An RL actor jointly outputs a **nominal** proposal mean `μ_nom`, a **risk level** `β`, and a **margin** `Δ`. A closed-form 2-D projection (their CVaR-BF quadratic program, reduced to a halfspace clip because `ln Y | θ` is Gaussian and `σ` is independent of the clipped coordinate, matching their Eq. 21–22) then produces the *applied* sampling mean `μ*` that actually draws `θ`, enforcing the chance constraint `P(Y>v | θ=μ*) ≥ 1−β` plus the learned margin. The actor is trained on the same scalar `tail_reward` as JEPA; the *filter* uses the closed-form Gaussian/lognormal leaf (same privilege family as G-PMC AIS, unlike JEPA). Their GMM mode-wise lemma is not used: given `θ`, aleatory shaking is unimodal Gaussian, so there is one mode and one constraint. `β` is initialized so that `1−β` starts at the experiment's tail mass (0.05 at the 95th percentile) and is learned jointly with `Δ`.
- **QR-SRM AIS** (`methods/qr_srm.py`): an adaptation of Moghimi & Ku (ICML 2025), *Beyond CVaR: Leveraging Static Spectral Risk Measures for Enhanced Decision-Making in Distributional Reinforcement Learning* (https://arxiv.org/abs/2501.02087, OpenReview `WeMpvGxXMn`). A **Spectral Risk Measure (SRM)** (Acerbi 2002) weights the quantile function of an outcome by a spectrum `φ`; CVaR is the special case with all mass on one tail, and any SRM is also a convex combination of CVaRs at several levels (Kusuoka 2001) — including **Mean-CVaR** `λ E[Y] + (1−λ) CVaR_α(Y)`, the paper's highlighted special case. Their Algorithm 1 alternates an *outer* closed-form update of a concave utility `h` from a quantile representation of the current return law, and an *inner* quantile-regression policy update that greedily maximizes `E[h(G)]`. Here the environment is a one-step `θ → Y` draw, so there is no sequential `(s, c)` augmentation and no Pflug–Pichler dual decomposition of later-stage risk: the outer step is an IS-weighted pinball update of an `N=32` quantile grid of `Y`, and the inner step is the same Gaussian CE/PMC moment-match used by G-PMC / JEPA v2. The paper's concave utility includes a quantile offset `q` that does not depend on the sample; CE/PMC uses *normalized* weights, so that offset is dropped and the remaining upper-CVaR piece is `(y − q)_+` (analog of their `[z − q]_-`), mixed with `y` itself for Mean-CVaR. Using `max(y, q)` would leave a near-constant body weight and starve the tail signal. Default spectrum is a Kusuoka mix of upper CVaRs at `α ∈ {0.05, 0.10, 0.25}` (the paper's "beyond CVaR" point); Mean-CVaR is available but a large `λ` leaves too much body mass for rare-event IS. The sign is flipped relative to the paper (they SRM the *lower* tail of returns; we put spectrum mass on the *upper* tail of shaking `Y`). **Never given `P(Y>v|θ)`.**
- **Hierarchical JEPA-CVaR v2**: keeps the Manager/Worker/JEPA structure but replaces v1's single-episode REINFORCE update with the *same batched closed-form CE/PMC weighted refit that `G-PMC AIS` uses* — except the relevance `H(θ)` it refits toward is the **empirical** `y·1{y>v}` realized on each sampled episode (no closed-form hazard formula involved), which is mathematically the same quantity as `tail_reward`. Concretely, per batch of `batch_size=300`:
  1. Sample `θ`s (again with a defensive mixture, plus a **windowed mixture** twist: the importance-weight denominator for `θ` is averaged over the last `mixture_window=6` proposals actually used, not just the newest one, to keep the ratio from blowing up as the proposal narrows — the AMIS/Deterministic-Mixture-PMC fix described earlier).
  2. For each `θ`, the Worker predicts a mean-shift `δ(θ)` to `ln Y | θ` (the "y-tilt"), clipped to `±tilt_cap·σ(θ)` (`tilt_cap=1.0`) — the stability fix described in the Experiments section, without which the exponential Girsanov importance-weight ratio `exp(δ²/2σ²)` becomes heavy-tailed whenever the tilt is large and informative.
  3. Draw `Y` from the tilted law, form the combined importance weight (`θ`-side ratio × the closed-form Gaussian-mean-shift ratio for the `y`-tilt), optionally PSIS-smooth it (fit a Generalized Pareto Distribution to its upper tail and replace the most extreme weights with the fitted order statistics, reporting `k_hat`), and use the resulting weight to compute `r = y·1{y>v}` for every episode in the batch.
  4. Refit the `θ`-proposal's mean/covariance by weighted moment-matching against `r` (identical formula to `G-PMC AIS`, just with an empirical weight instead of a closed-form one) — this *is* "the CVaR policy being computed": the sampling distribution is periodically re-estimated to look like a weighted average of whichever recent `θ`s happened to land large tail contributions.
  5. Refit the Worker's tilt readout `(Wy, by)` by weighted least squares (ordinary weighted linear regression) against the same `r`, predicting the realized `ln Y` residual from the JEPA embedding.
  The **Manager/Worker short-vs-long-horizon split survives into v2 as an update-***cadence*** split rather than a learning-rate split: the *fine* JEPA (feeding the Worker's per-`θ` tilt) is retrained every `jepa_train_every=16` individual episodes, while the *coarse* JEPA (whose embedding of the batch's current proposal mean conditions the fine one, giving the Worker context about "which region the Manager currently occupies") is retrained only every 4 *accumulated batches* — roughly every 1,200 episodes — on a coarser, batch-aggregated summary (mean scaled reward, exceedance rate, and mean `log(1+y)` for the whole batch). So "short horizon" = re-fit every 16 episodes on individual outcomes; "long horizon" = re-fit roughly every 1,200 episodes on a batch-level summary — genuinely different timescales of adaptation, not different episode lengths.

### Spatial portfolio methods (`Naive MC`, `Flat REINFORCE`, `CVaR-CPO`, `Hierarchical`)

The tree here has four sequential decision levels — geometry, GMM (together the **Manager**'s levels), then magnitude, then rupture location (the **Worker**'s levels) — enumerating to `2 × 3 × 16 × 20 = 1,920` complete paths; one episode is a full four-step walk to a leaf, with the portfolio loss `L = Σ_k PGA_k` (summed Peak Ground Acceleration over all 10 sites) taking the place of `Y`, and the leaf reward `r_T = (∏ w/q over all 4 steps) · L · 𝟙[L > v95]` computed once at the end, exactly like the 3-node tree.

- **Naive MC** and **`Flat REINFORCE`** are the direct spatial analogs of their 1-node/3-node counterparts (`Flat REINFORCE` = one 1,920-way softmax over full paths, same score-function update as before).
- **`CVaR-CPO`** adds the same dual-variable CVaR-drift penalty and trust-region KL damping described for the tree version, plus one more regularizer: every so often, `q`'s logits are pulled part-way back toward the nominal prior's logits (`prior_kl_coef`), keeping the learned policy from drifting arbitrarily far from the physically-motivated branch weights even under sustained reward pressure.
- **Hierarchical** decomposes the policy into one small softmax per node/history, as in the 3-node case, but adds three refinements: (1) the Manager's two levels (geometry, GMM) update with a smaller learning-rate multiplier (`manager_lr_scale=0.6`) than the Worker's two levels (`worker_lr_scale=1.0`) — again the same slow-anchor/fast-correction split as JEPA-CVaR, this time as a direct per-level learning-rate multiplier rather than a separate Manager/Worker parameterization; (2) a softmax **temperature** (a scaling factor that controls how sharp or spread-out a probability distribution is — dividing logits by a larger temperature flattens the distribution toward uniform, by a smaller one sharpens it toward a single best action) is annealed from `1.25` down to `0.95` over the run, and an **entropy bonus** (an extra term in the update that rewards keeping probability spread across actions, discouraging premature collapse onto one path) is annealed from `0.05` down to `0.01`, both loosening exploration early and tightening it later; (3) **Generalized Advantage Estimation (GAE)** — a technique (Schulman et al. 2016) for spreading a single trajectory's final reward back across every intermediate decision using a recursive, exponentially-weighted blend of one-step and multi-step credit, controlled by a decay parameter `λ_GAE=0.9` — is computed per depth and blended 50/50 with the plain shared-baseline advantage used elsewhere, giving the four decision levels (geometry, GMM, magnitude, rupture) somewhat different credit for the same leaf outcome rather than all four receiving the identical scalar.

### Continuous epistemic space (paper 2 style)

Median-**GMPE** (Ground Motion Prediction Equation — same concept as GMM above, the model predicting shaking intensity) offset and aleatory-sigma scaling as a **continuous** bivariate Gaussian prior `θ = (θ_μ, θ_σ)` instead of discrete branches (`continuous_env.py`). Here `θ` (theta) denotes the two unknown model parameters being treated as continuously uncertain: `θ_μ` is an unknown offset shifting the median predicted shaking, and `θ_σ` is an unknown multiplier scaling the aleatory (irreducible, run-to-run) standard deviation `σ` introduced above. "Bivariate Gaussian prior" means our starting belief about `(θ_μ, θ_σ)`, before any data/reward is used, is a two-dimensional Normal distribution. Ground truth is computed by **Gauss-Hermite quadrature** (`continuous_ground_truth.py`) — a numerical-integration technique that evaluates a function at a small set of carefully chosen points ("nodes"), each with a matching weight, so that a Gaussian-weighted integral comes out essentially exact (up to the chosen number of nodes), with none of the random sampling noise that Monte Carlo simulation would introduce. This was cross-checked against a 20-million-sample brute-force Monte Carlo run (~3e-4, i.e. about 0.03%, relative error).

Methods compared:
- **Naive MC** — plain Monte Carlo: samples straight from the nominal prior `p`, with no importance-sampling reweighting at all (the "do nothing clever" baseline).
- **Disagg-IS oracle** — samples a Gaussian moment-matched (i.e., fit by matching its mean and covariance, its first two "moments," to) the exact `q_disagg` grid — a static upper baseline that doesn't adapt.

- **Hierarchical JEPA-CVaR v1** — the original learning agent (`methods/jepa_cvar.py: run_jepa_cvar`), kept for comparison. **Never sees `P(Y>v|θ)`** — only the scalar reward. "JEPA" stands for **Joint Embedding Predictive Architecture**, a neural-network design (introduced by Yann LeCun) that learns by predicting a compressed, abstract representation ("embedding") of unseen/future data rather than the raw data itself; here it's used as the internal representation the agent builds of the epistemic space.
- **Hierarchical JEPA-CVaR v2** — a corrected agent (`methods/jepa_cvar.py: run_jepa_cvar_v2` + `jepa.py`), replacing v1's heuristic update rule with a theoretically-motivated one (below). **Also never sees `P(Y>v|θ)`.**
- **CVaR-BF AIS** — Wang et al. (2026) CVaR-barrier filter (`methods/cvar_bf.py: run_cvar_bf_ais`). The QP/chance-constraint layer *does* use the closed-form Gaussian leaf (see method reference above); the actor does not see `P(Y>v|θ)` as an IS target, only `tail_reward`.
- **QR-SRM AIS** — Moghimi & Ku (ICML 2025) static SRM / quantile-regression agent (`methods/qr_srm.py: run_qr_srm_ais`). Default training objective is a Kusuoka mix of upper CVaRs; reported metric is still CVaR at `v95`. **Never sees `P(Y>v|θ)`.**

**What v1 got wrong, and what v2 fixes.** v1's "CVaR" mechanism was a **dual variable** — in constrained optimization, an auxiliary number (a Lagrange multiplier) that grows or shrinks to penalize violating some constraint — penalizing drift of the running CVaR *estimate*. This was a heuristic copied from this repo's `cvar_cpo.py` (itself labeled "lightweight discrete **CPO**," where CPO = **Constrained Policy Optimization**, an RL algorithm that updates a policy to maximize reward while provably keeping a separate cost/risk signal under a bound — not a rigorous CVaR policy gradient), and my original text here cited the Tamar and Chow & Ghavamzadeh CVaR-policy-gradient/CPO papers as the target to aim for. That citation was a mismatch: those papers solve risk-averse RL over *an agent's own returns*; our actual problem is *adaptive importance sampling to minimize the variance of a CVaR estimator of a fixed external `Y` under a fixed nominal prior `p`* — the classical Cross-Entropy / Population Monte Carlo literature (de Boer, Kroese, Mannor & Rubinstein 2005; Cappé et al. 2004), which `gpmc_ais.py` already implements correctly.

v2's fix follows directly from that reframing: the Cross-Entropy (CE) method fits a proposal `q_φ` (a Gaussian with parameters `φ`) by minimizing `KL(q*, q_φ)`, the **Kullback–Leibler (KL) divergence** — a standard, always-nonnegative measure of how different one probability distribution is from another, defined as `KL(P,Q) = Σ_x P(x)·log(P(x)/Q(x))`, equal to zero exactly when the two distributions match — from the true CE-optimal target `q*(x) ∝ p(x)·H(x)` (where `H(x)` stands for whatever quantity is being targeted — e.g., a rare-event indicator, or here the CVaR-relevant severity, defined next) to our fitted proposal `q_φ`. For a Gaussian family, minimizing this KL divergence works out to a **weighted moment-matching** update: refit the proposal's mean and covariance (its first two "moments") as a weighted average/covariance over samples, using weights `w(x) = p(x)·H(x)/q_ref(x)` (the importance-weight formula from the introduction, generalized to include the target function `H`). G-PMC AIS uses the closed-form `H(θ) = P(Y>v|θ)`; **the only thing requiring closed-form access is the choice of `H`, not the refit mechanism** — so v2 substitutes the single-rollout empirical outcome `H(θ,y) = y·1{y>v}` (read: "the observed severity `y`, but only counted when it exceeds the threshold `v`; `1{·}` is an indicator function equal to 1 when the condition in braces holds, and 0 otherwise"), and `p(θ)·H(θ,y)/q(θ)` turns out to be exactly `estimators.tail_reward`, the per-sample importance-weighted severity already used everywhere in this repo as the scalar reward. v2 also tilts the full joint distribution — adding a learned mean-shift `δ(θ)` (delta, a small offset in the shaking distribution's mean, refit by **weighted least squares**, i.e. a linear regression that minimizes squared error while giving each sample's error a different importance-based weight) to `ln Y | θ` — and composes two `LightweightJEPA` instances (a coarse region embedding feeding a fine one). All three additions were validated before the full run:
- Weighted moment-matching and weighted least-squares formulas checked against synthetic known-target recovery (≤3e-4 error).
- The learned `δ(θ)` was checked against a closed-form target — **not** the naive `σ(θ)²` (the squared aleatory standard deviation) untruncated-tilt originally proposed, since that ignores the effect of conditioning on `Y>v`, which itself shifts the mean further. The correct target is the mean of the *truncated-tilted* normal distribution (i.e., a Normal distribution whose mean has been shifted, and which is then restricted/conditioned to only its upper tail beyond `v`): `μ + σ² + σ·φ(α)/(1−Φ(α))`, where `φ` is the standard normal probability density function, `Φ` is the standard normal cumulative distribution function, and `α = (ln v − μ − σ²)/σ` is the threshold `v` expressed in standardized units. Learned values (1.16–1.56 across 4 test θ) tracked this corrected target (1.24–1.60) well, confirming the fit learns the right quantity.

**Result, initial v2 (budget=20k, 10 replications; ESS from a separate 8-replication check) — before the ESS investigation below; superseded by the "current defaults" table at the end of this section:**

Two new terms appear in the table: **ESS (Effective Sample Size)** is a diagnostic for importance-sampling estimators, measuring how many "effectively independent" samples a set of unevenly-weighted samples is really worth. It's computed as `ESS = (Σ W)² / Σ W²`, where `W_i` are the samples' importance weights and the sums run over all samples: if all weights are equal, ESS equals the total sample count `N` (as good as ordinary Monte Carlo); if one sample's weight dominates all others, ESS collapses toward 1 (nearly all the statistical information really comes from a single draw — a red flag for reliability, even if the raw sample count `N` looks large). **RMSE (Root Mean Square Error)** is `sqrt(mean((estimate − true value)²))` computed over repeated independent runs ("replications"), summarizing both bias and variance of an estimator's accuracy in one number — smaller is better.

### What's still not "the real thing" — and a reliability caveat that qualifies the CVaR-RMSE win

Even v2 is not unqualified: the JEPA encoders are still linear/toy-scale (not the full I-JEPA/V-JEPA architectures from the original JEPA research), the y-tilt keeps aleatory variance fixed (no learned scale), and the coarse/fine JEPA composition, while genuinely two-level, is simple (batch-aggregated coarse signal, not a learned multi-step abstraction hierarchy). The KS gap to G-PMC AIS, while narrowed, hasn't closed.

More importantly, the CVaR-RMSE win above needs a real caveat, found by checking ESS (this project's own policy-collapse diagnostic, defined above) rather than taking the RMSE number at face value: over 8 replications, **v2's ESS is 100 ± 74 out of a 20,000 budget (~0.5%)** — one replication had ESS = 5. G-PMC AIS's ESS is 6,099 ± 75 over the same runs; v1's is 2,577 ± 739. A low, unstable ESS means v2's **self-normalized IS estimator** — an importance-sampling estimator that divides by the sum of the sample weights, `(Σ wᵢ·f(xᵢ))/(Σ wᵢ)`, rather than by the true count `N`, useful when the target's normalizing constant isn't known exactly, at the cost of a small bias that shrinks as more samples are drawn — is, within many individual runs, dominated by a handful of samples. This is a known pathology of using the raw severity `y·1{y>v}` (heavy-tailed, since `Y` is lognormal) as an unclipped CE moment-matching weight, only partly offset by the 10% **defensive-mixture floor** — a technique where the sampling proposal always retains at least some minimum fraction (here 10%) of probability mass from the original nominal distribution `p`, which caps how extreme any single importance weight can get.

**Tried: Pareto-Smoothed Importance Sampling (PSIS)** (Vehtari, Gelman & Gabry 2024; `psis.py`) — the standard Stan/ArviZ/`loo`-ecosystem fix for exactly this pathology. PSIS works by fitting a **Generalized Pareto Distribution (GPD)** — a probability-distribution family commonly used to model the extreme tail of another distribution, with a shape parameter conventionally called `k` (or ξ) controlling how heavy that tail is: larger `k` means more extreme outliers are likely, and `k ≥ 1` means the distribution's mean is not even finite — to the upper tail of the importance weights, and replacing those extreme weights with the fitted distribution's smoothed order statistics (i.e., swapping the few largest raw weights for values predicted by the fitted GPD curve, damping any single runaway outlier). The fitted shape, denoted `k_hat`, doubles as a built-in reliability diagnostic: by the convention established in the PSIS literature, `k_hat > 0.7` means "don't trust this estimate," independent of what the ESS number says. We use scipy's GPD **Maximum Likelihood Estimation (MLE)** — a general statistical method that fits a distribution's parameters by choosing whichever values make the observed data most probable — rather than hand-implementing the original paper's Zhang–Stephens small-sample estimator (a more specialized fitting procedure tuned for few tail samples); this is documented as a simplification, not a reproduction of the reference implementation, and was validated against synthetic GPD samples with known shape before use (recovers `k` reasonably well; on a synthetic single-huge-outlier case it correctly reports `k_hat≈10` and declines to pretend to fix it). Applied to `iw` (the codebase's variable name for the importance weights) itself, not a hidden internal copy — consistent with how **PSIS-LOO** (PSIS applied to Leave-One-Out cross-validation, its most common use in Bayesian model-checking) is actually used in practice.

**Result (budget=20k, 10 replications, paired seeds before/after):**

| | ESS (mean ± std) | CVaR RMSE | `k_hat` (mean) |
|---|---|---|---|
| v2, no PSIS | 88.4 ± 61.5 | 0.0080 | — |
| v2, with PSIS | **300.8 ± 51.6** | 0.0076 | **0.93–1.02 across all 10 reps** |

PSIS gives a real, measurable improvement — ESS roughly **3.4× better on average**, with no meaningful change (and no bias) in CVaR accuracy. But `k_hat` sits at ~0.9–1.0 in *every single replication*, consistently above the paper's own 0.7 reliability threshold. Read plainly: **PSIS confirms the original diagnosis was correct** (an independent, more principled diagnostic agrees the weight tail is problematic) **and provides partial relief, but is honestly telling us it cannot fully fix this** — the tail is heavier than even GPD-smoothing can safely characterize at this sample size. This is exactly the outcome PSIS is designed to surface, not a failure of the implementation.

**Tried: windowed Deterministic-Mixture PMC / AMIS** (Cornuet, Marin, Mira & Robert 2012; Elvira, Martino, Luengo & Bugallo 2019) — **AMIS** (Adaptive Multiple Importance Sampling) evaluates each sample against the mixture of the last `mixture_window` proposals actually used (a bounded-memory version of the **balance heuristic**, a rule from multiple-importance-sampling theory for combining samples drawn from several different proposal distributions by weighting each sample against the sum of all those proposals' densities, rather than against just the single proposal it happened to be drawn from) — testing the hypothesis that an increasingly-narrow adapted proposal creates extreme `p(θ)/q(θ)` ratios for off-mean draws. **Result: essentially no effect.** Sweeping `mixture_window` (the hyperparameter controlling how many recent proposals are included in the mixture) ∈ {1, 3, 6, 12} moved ESS and KS by amounts consistent with noise, not a trend — and checking directly, the proposal's covariance wasn't collapsing much (the **determinant ratio** — the ratio of the current proposal covariance matrix's determinant, which reflects the "volume" of its spread, to the original prior's determinant — was ≈0.57 vs the prior, not orders of magnitude smaller). Wrong root cause: the θ-side proposal narrowing this technique targets wasn't actually the dominant problem here.

**Found the real root cause, and a fix that worked:** disabling the joint (θ,y) tilt entirely (setting the codebase flag `enable_joint_tilt=False`, which turns off the learned mean-shift `δ(θ)` described above) took raw ESS from 24 to **4,952** — a ~200× jump — at the cost of KS degrading from 0.026 to 0.32. That isolates it: **the y-tilt itself (Gap 2 from the original review) is the dominant source of weight degeneracy**, not the θ-refit. The mechanism: `iw_y`'s **Girsanov ratio** — a result from stochastic-process theory giving the likelihood ratio (the factor by which probability density changes) between two distributions that differ by a mean shift — grows like `exp(δ²/2σ²)`, i.e. exponentially in the *square* of the shift `δ` relative to the standard deviation `σ`. So whenever the learned tilt `δ(θ)` is large relative to `σ(θ)` — which is exactly the well-fitting, informative regime confirmed by the closed-form cross-check earlier — the likelihood ratio itself becomes heavy-tailed. Rather than disabling the tilt entirely (throwing away real signal), we cap it: `δ(θ) ← clip(δ(θ), ±tilt_cap·σ(θ))`, where `clip(x, ±a)` means "restrict `x` to the range `[−a, a]`, truncating anything outside that range to the nearest boundary," and `tilt_cap` is a hyperparameter setting how many standard deviations `σ(θ)` the tilt is allowed to shift the mean by.

**Result (budget=20k, 10 replications, `tilt_cap=1.0`, combined with PSIS + windowed mixture):**

| | ESS (mean ± std) | `k_hat` (mean) | CVaR RMSE | KS vs `q_disagg` |
|---|---|---|---|---|
| v2, PSIS only | 300.8 ± 51.6 | 0.96 (unreliable) | 0.0076 | 0.068 ± 0.023 |
| **v2, + tilt_cap=1.0** | **2,480 ± 162** | **0.49 (reliable)** | 0.0114 | 0.120 ± 0.064 |
| G-PMC AIS (reference) | 6,089 ± 74 | — | 0.0327 | 0.038 ± 0.007 |

This is a genuine trade-off, not a clean win, and a single-seed test I ran first (which looked like a win on all three metrics at once) didn't survive averaging over 10 replications — worth flagging since it's exactly the kind of result that's tempting to report from one lucky run. Capping the tilt is the first change in this whole investigation to push `k_hat` **below the 0.7 reliability threshold on average** — i.e., the first version where the PSIS diagnostic itself says "this is now trustworthy" — at a real cost to both KS and CVaR RMSE (though CVaR RMSE, 0.0114, remains ~3× better than G-PMC AIS's). Since the point of the ESS/`k_hat` checks was to determine whether the earlier "v2 beats G-PMC AIS" claim could be trusted, and a diagnostically-reliable estimator matters more than a diagnostically-flagged one with a marginally better point estimate, **`tilt_cap=1.0` (combined with `mixture_window=6` and PSIS) is now the default** for `run_jepa_cvar_v2`, even though it reports a less flattering headline number than the uncapped version did.

**What's left, if pursued further:** a learned (rather than fixed) tilt cap, or a per-sample soft penalty on `δ²/σ²` in the refit objective instead of a hard clip; re-deriving the joint-tilt target to account for the truncation-vs-variance trade-off directly rather than capping after the fact; more replications to check whether the windowed-mixture null result holds at other budgets.

### 2D multi-site portfolio hazard MDP

Fault-line ruptures, \(K=10\) sites (ten separate geographic locations whose shaking is jointly modeled), Gutenberg–Richter magnitude bins — the **Gutenberg–Richter law** is a well-established empirical relationship in seismology stating that the number of earthquakes of magnitude ≥ M falls off exponentially as M increases; "bins" means magnitude is discretized into intervals for the logic tree — plus epistemic geometry + GMM (handled by a **Manager**, the higher level of a two-level hierarchical decision-maker) and magnitude + rupture location (handled by a **Worker**, the lower level, which decides conditional on the Manager's choice).

Portfolio loss \(L = \sum_k \mathrm{PGA}_k\) — the total loss, defined as the sum across all `K` sites of each site's **Peak Ground Acceleration (PGA)**, the maximum ground acceleration experienced during the earthquake and one of the most common measures of shaking intensity — under a distance-attenuated GMPE footprint (the pattern of predicted shaking across all sites, produced by the GMPE introduced earlier, that weakens/"attenuates" with distance from the rupture). Leaf reward — the scalar reward computed only once, at the end ("leaf") of a full decision sequence through the tree:

```text
r_T = (prod_t w/q) * L * 1{L > v95}
```

Here `prod_t w/q` means "multiply together, across every decision step `t` in the path, that step's importance weight `w` divided by the sampling probability `q` the agent actually used" — accumulating the total importance-weight correction for the whole sampled path — and `1{L > v95}` is the indicator function from earlier, equal to 1 only when the total portfolio loss `L` exceeds the 95th-percentile threshold `v95`.

Methods: Naive MC, Flat REINFORCE (REINFORCE applied without any hierarchical structure), **CVaR-CPO** (this repo's lightweight, discrete adaptation of Constrained Policy Optimization aimed heuristically at CVaR — explicitly not a rigorous CVaR policy-gradient method, as flagged earlier), **Hierarchical** (~1920 joint paths, i.e. Manager/Worker decision sequences).

## Ground truth & disaggregation (`disaggregation.py`, `continuous_ground_truth.py`)

For lognormal leaves (`ln Y | s ~ N(μ_s, σ_s)` — read: "given scenario `s`, the log of shaking `Y` is Normally distributed with scenario-specific mean `μ_s` and standard deviation `σ_s`"), VaR, CVaR, and both IS targets are **closed-form** — i.e. computable by exact formula, not simulation:

- `q_disagg(s) ∝ p(s) · P(Y>v | s)` — Houng & Ceferino (2025)'s proven-optimal target for exceedance-probability estimation (the classical hazard disaggregation distribution, defined at the top of this document).
- `q_star(s) ∝ p(s) · E[Y · 1{Y>v} | s]` — our severity-weighted extension, the correct IS target for CVaR's numerator (`E[·]` denotes an expected value/average). **Not** proven in the source papers; kept distinguished from `q_disagg` throughout.

VaR is solved exactly via 1-D root-finding — numerically solving a single-variable equation `f(x)=0` (e.g., by bisection search) — on the closed-form mixture CDF (the cumulative distribution function of `Y` when `Y`'s overall distribution is a weighted combination, or "mixture," over all the logic-tree branches/scenarios), rather than via `np.quantile` (NumPy's function for estimating a quantile empirically from a finite sample, which carries sampling noise that the closed-form approach avoids entirely). For the continuous environment, Gauss-Hermite quadrature nodes/weights (defined earlier) stand in for "priors, mus, sigmas," so the same closed-form machinery is reused unchanged. All closed forms were cross-checked against large-N brute-force Monte Carlo before use (see git history / `disaggregation.py`, `continuous_ground_truth.py` docstrings).

## Metrics

- **CVaR convergence** toward the large-sample / closed-form true portfolio CVaR (defined at the top of this document).
- **ESS** = `(Σ W)² / Σ W²` — the Effective Sample Size formula introduced above, used throughout this project to detect *path-policy collapse* (an agent's sampling policy degenerating so that only a handful of paths carry all the statistical weight, even though many were nominally sampled).
- **KL / TV / KS** of a method's final sampling distribution against `q_star` and `q_disagg` (`metrics.py`): **KL** is the Kullback–Leibler divergence defined above; **TV** is **Total Variation distance**, another way of comparing two probability distributions, informally the largest possible difference in probability the two distributions could ever assign to the same event (0 = identical, 1 = no overlap at all); **KS** is the Kolmogorov–Smirnov distance defined above — the categorical analog of the KS-D metric both source papers report, for direct comparability.
